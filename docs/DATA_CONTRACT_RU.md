# Контракт данных ContentFactory v2.1

## Версия контракта

Каждый канонический пакет содержит `schema_version: "2.1"`. Следующие модули должны проверять это поле до чтения сцен и заданий.

## Канонический объект

`production_package.json` — единственный источник содержания. Файлы `script.txt`, `storyboard.json`, `visual_prompts.json`, `asset_requirements.json`, `continuity_guide.json` и `timeline.json` являются экспортами для конкретных потребителей и не должны редактироваться независимо.

## Данные, которые создаёт Gemma

- `project` — тема, площадка, аудитория, тон и целевая длительность.
- `research_brief` — центральный тезис, ключевые пункты, фактические утверждения, материалы и пробелы.
- `script` — окончательная озвучка и её ориентировочные метаданные.
- `visual_style` — общий язык изображения и реестр повторяющихся сущностей.
- `scenes` — последовательность визуальных задач, длительность, текст озвучки, тип ресурса и промпты.
- `editing_plan` — монтажные предпочтения и правило учёта заставки/финала.
- `human_review` — дополнительные проверки редактора.

## Контракт типов ресурсов

| Тип | Нужен image_prompt | Нужен video_prompt | Нужен motion_prompt | Выход |
|---|---:|---:|---:|---|
| generated_image | Да | Нет | Нет | PNG |
| image_animation | Да | Нет | Да | PNG + MP4 (FFmpeg camera move) |
| ai_video | Да | Да | Нет | reference PNG + MP4 (Wan) |
| motion_graphic | Да | Нет | Да | MP4 (SVG/FFmpeg) |
| stock_or_archive | Да (поисковая фраза) | Нет | Нет | найденный файл, выбранный человеком |

Неиспользуемые prompt-поля — пустые строки. Этот контракт нужен для предсказуемой маршрутизации, а не для стилистики.

## Непрерывность сущностей

`visual_style.continuity_entities` содержит стабильные ID и точные канонические описания повторяющихся людей/объектов/мест. Сцена указывает применимые ID в `continuity_entity_ids`. Если ID указан, `canonical_description` должен дословно присутствовать в `image_prompt`.

## Реестр фактов

Если claim используется в озвучке, `used_in_script=true`, а `script_excerpt` дословно содержится в `script.full_text`. Если утверждение не используется, `used_in_script=false` и `script_excerpt=""`.

Структурная привязка не доказывает истинность claim. Все утверждения остаются в `human_review.txt`: непроверенные требуют сверки по надёжным источникам, а `verified_in_user_material` — проверки того, что переданный материал действительно подтверждает формулировку. Статус, выставленный Gemma, не является доказательством. Модель не имеет доступа к интернету на этом этапе.

## Хронометраж

Сумма `scenes[].duration_seconds` равна `project.target_duration_seconds` с допуском 0,01 секунды. Заставка, затемнение, переходы и финальная выдержка включаются в длительность соответствующей сцены. `timeline.json` — предварительная временная шкала уровня сцен. После TTS необходимо синхронизировать её с реальным аудио.


## Дополнения v2.2 (обратная совместимость)

- `scenes[].visual_anchor_terms`: 2–5 коротких английских фраз с обязательными видимыми объектами; каждая фраза должна дословно присутствовать в `image_prompt`.
- `scenes[].motion_target`: для `image_animation` — цель camera-only движения, присутствующая в `image_prompt` и `motion_prompt`; для остальных маршрутов пустая строка.
- `editing_plan` принимает параметры оформления субтитров и аудиомикширования, добавляемые по локальному профилю, если они отсутствуют.
- `schema_version` остаётся `2.1`; поля v2.2 объявлены необязательными в схеме ради совместимости, но обязательны при запуске новой генерации ContentFactory 2.2.


## Дополнения v2.2.0

- `visual_purpose` для новых пакетов формулируется на английском как конкретное описание того, что зритель видит в кадре.
- `visual_anchor_terms` содержит 2–5 коротких английских фраз, которые дословно встречаются и в `visual_purpose`, и в `image_prompt`. Для `ai_video` все якоря должны присутствовать и в `video_prompt`.
- `motion_target` для `image_animation` должен совпадать с одним из `visual_anchor_terms` и дословно присутствовать в `image_prompt` и `motion_prompt`.
- `image_animation` использует только движение камеры; физическое движение объектов требует другого маршрута.
- Локальный профиль по умолчанию ограничивает `ai_video` двумя сценами на ролик; лишние промежуточные Wan-сцены переводятся в `image_animation` с записью в `human_review`.
- `schema_version` остаётся `2.1` для чтения существующих пакетов; версия приложения хранится централизованно в `VERSION.txt`.
- Продолжительность сцен перераспределяется после синхронизации дословного текста озвучки, по числу слов и границам предложений. Фактические таймкоды подтверждаются только после TTS.

- Ручной `tools/Validate-Package.ps1` по умолчанию совместим со старыми пакетами; для полного профиля v2.2 передаются `-RequireVisualAnchors -MaxAiVideoScenes 2`. Основной `factory.ps1` всегда использует строгий профиль из `config/settings.json`.


## Identity reference персонажей (v2.2)

Если сущность типа `person` используется минимум в двух сценах, детерминированный repair добавляет `reference_asset_path` (`assets/characters/<entity_id>_reference.png`) и `reference_image_prompt`, включающий canonical description. Экспорт `asset_requirements.json.character_references` описывает генерацию и ручное утверждение PNG. `visual_prompts.json.scenes[].continuity_reference_assets` связывает каждую использующую сцену с путём к identity reference. Сам PNG ContentFactory не создаёт.


## Разделение visual anchors и continuity (v2.2.4)

`visual_anchor_terms` — это 2–5 ключевых сюжетных объектов/субъектов конкретной сцены. Каждый якорь должен дословно присутствовать в `visual_purpose` и `image_prompt`; для `ai_video` — также в `video_prompt`. Возраст, одежда, причёска, свет, цветовая палитра и другие детали внешности из `canonical_description` сами по себе не являются сюжетными якорями. Они сохраняются в prompt как continuity details.

Для `image_animation` поле `motion_target` должно быть одним из visual anchors и существовать в исходном изображении и camera-only `motion_prompt`. Нельзя направлять камеру на объект, которого нет в кадре.

Если первый ответ Gemma нарушает эти правила, ContentFactory 2.2.5 выполняет отдельный короткий запрос с `think=false` для каждой проблемной сцены. Разделение запросов снижает риск смешивания полей разных сцен и маршрутов. Ответ применяется только после локальной строгой проверки. `voiceover_text`, длительности и claims не меняются. Для camera-only задачи `ai_video` безопасно переводится в `image_animation` (или в `generated_image`, если нет подтверждённой цели камеры); `image_animation` всегда очищается от `video_prompt`. Если ремонт не прошёл проверку, пакет остаётся заблокированным валидатором, а причина записывается в `human_review`.
